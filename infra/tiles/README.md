# infra/tiles — self-hosted basemap (I3.1)

The map is fully self-hosted (AGENTS.md §2/§7: no CDN, no third-party tile
hosts): one nginx serves the PMTiles basemap archive, the glyph PBFs, the
sprite sheets and the two MapLibre styles from a single origin on **port
8080**. Everything except the big archive is committed and serves immediately.

```text
infra/tiles/
  nginx.conf                 range/CORS/cache config (mounted by the compose tiles service)
  style.json|style.dark.json MapLibre styles — generated by `pnpm build:map:style`
  fonts/<stack>/<a>-<b>.pbf  glyph ranges — generated by `pnpm build:map:glyphs`
  sprites/sprite(@2x)...     sprite sheets  — generated by `pnpm build:map:sprite`
  data/tiles/iran.pmtiles    THE BASEMAP ARCHIVE — machine-local, see below
```

## 1. The basemap archive (`data/tiles/iran.pmtiles`)

Pinned provenance — do not substitute silently:

- **Source**: Protomaps OSM Basemap, **Version 4** schema
  (docs.protomaps.com/basemaps/layers — layers `boundaries`, `buildings`,
  `earth`, `landcover`, `landuse`, `places`, `pois`, `roads`, `transit`,
  `water`). DECISIONS 2026-11-09 (I3.1) records why v4.
- **Region**: Iran (protomaps.com/downloads → OSM basemaps → Iran PMTiles, or
  a Geofabrik `iran-latest.osm.pbf` converted with the
  [protomaps/basemaps](https://github.com/protomaps/basemaps) tile builder).
- **Placement**: put the file at `infra/tiles/data/tiles/iran.pmtiles`
  (git-ignored). The tile server boots and serves styles/fonts/sprites even
  without it — only `/tiles/iran.pmtiles` 404s and the map UI (F3.1) renders
  the degraded-but-usable state (no basemap context).
- **Verification**: `pnpm check:tiles` warns when the archive is missing or
  suspiciously small (<1MB). Record the file's SHA-256 + build date in the
  deployment notes when you install it (docs/DEPLOYMENT.md §4 procedure).

## 2. Serving

`pnpm services:up` starts the `tiles` container (`nginx:1.28-alpine`, pinned)
with `infra/tiles/nginx.conf`. Byte ranges are what make PMTiles work over
plain static hosting — the client fetches ~16KB windows via `Range` headers;
nginx answers with `Accept-Ranges: bytes` natively. CORS is open (`*`) because
the stack is public by design; caching: tiles 1 day, fonts/sprites immutable
1 year, styles `no-cache` (they embed the public tiles URL and regenerate).

Ports per AGENTS.md §4: tile server **8080**.

## 3. Styles

`pnpm build:map:style` writes `style.json` (light) + `style.dark.json` from
`scripts/lib/map-style.mjs` (one layer list, two palettes derived from the
`modern` theme pack in docs/DESIGN.md §2 — map-style=light|dark per mode).
The vector source URL is baked from `TILES_PUBLIC_URL` (default
`http://localhost:8080`); on a deployment with a public tile origin:

```sh
TILES_PUBLIC_URL=https://tiles.example.com pnpm build:map:style
```

Glyphs and sprites stay RELATIVE (`/fonts/...`, `/sprites/sprite`) —
origin-agnostic by design. `pnpm check:tiles` validates both styles against
the served artifacts (fonts referenced by symbol layers exist, sprite path
matches, no duplicate layer ids).

## 4. Fonts (glyph PBFs)

Self-hosted only (AGENTS.md §2). The variable-font TTFs sit in
`scripts/map-fonts/` (committed, OFL licenses included) and the checksums are
pinned in `scripts/check-tiles.mjs` — `pnpm check:tiles` fails on drift:

| File          | SHA-256 (prefix)    | Source                                                |
| ------------- | ------------------- | ----------------------------------------------------- |
| Vazirmatn.ttf | `696249a2…fd49dca`  | google/fonts `ofl/vazirmatn` (variable, Arabic+Latin) |
| Inter.ttf     | `29160a80…820dc559` | google/fonts `ofl/inter` (variable)                   |

`pnpm build:map:glyphs` pins each weight (`wght` axis) and emits the six
MapLibre font stacks — `Vazirmatn Regular/Medium/Bold`, `Inter
Regular/Medium/Bold` — as 256-codepoint PBF ranges covering Latin, Arabic
(incl. Persian digits), Arabic Extended and General Punctuation (ZWNJ
0x200C). The style layers use **single-font stacks** only; Persian labels
pick the stack via layer (`Vazirmatn Bold` for cities, `Medium` for towns,
`Regular` for roads/villages) and prefer `name:fa` over the local `name`.

## 5. Sprites

`pnpm build:map:sprite` rasterizes the inline SVG icon sources in
`scripts/build-map-sprite.mjs` into `sprite.png/json` + `@2x` (pixelRatio 2)
via sharp. The basemap layers reference no icons (fills/lines/labels only);
the seed set is the app marker pin for the F3.x map components.

## 6. Client contract (consumed by F3.1)

- Style URL: `${NEXT_PUBLIC_TILES_URL}/style.json` (light) or
  `/style.dark.json` (dark mode) — `NEXT_PUBLIC_TILES_URL` defaults to
  `http://localhost:8080` (apps/web/src/lib/env.ts).
- The client must register the `pmtiles://` protocol with MapLibre before
  loading the style (the style's vector source is
  `pmtiles://<origin>/tiles/iran.pmtiles`) — the official
  [`pmtiles`](https://github.com/protomaps/PMTiles) adapter provides it.
- Persian labels need MapLibre's RTL text support — verify the plugin /
  built-in RTL behavior in F3.1 when the first labeled map renders.
